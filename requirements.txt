# --- PyTorch --------------------------------------------------------------
# MUST come from the cu128 index. The RTX 5070 Ti is Blackwell (sm_120), which
# the default PyPI wheels (cu126 and older) do not contain kernels for: they
# install fine and then fail at the first kernel launch with
# "no kernel image is available for execution on the device".
# cu128 wheels are forward-compatible with the A6000s (sm_86).
--extra-index-url https://download.pytorch.org/whl/cu128
torch==2.9.1+cu128
torchvision==0.24.1+cu128

# --- Detector -------------------------------------------------------------
# Ultralytics is NOT installed from PyPI. It is cloned as a sibling of this repo
# and installed editable, so custom modules (the MoE block) can be added later
# without vendoring a fork (see 04-method-open-questions.md, framework decision).
#
#     git clone https://github.com/ultralytics/ultralytics.git ../ultralytics-src
#     git -C ../ultralytics-src checkout 98a9cfde3119079568620bd43c26bb541c61ac8d
#     pip install -e ../ultralytics-src --no-deps
#
# PINNED COMMIT: 98a9cfde3119079568620bd43c26bb541c61ac8d   (tag v8.4.115)
#
# Two traps, both hit and fixed rather than theoretical:
#
# 1. `git ls-remote --tags` returns 8fbfccb8e6139f4e995f55d1272dc96e66699346 for
#    v8.4.115, but that is the ANNOTATED TAG OBJECT, not a commit. `git checkout`
#    peels it to the commit above, so checking it out works — but `git log` on it
#    does not, and calling it "the commit" is wrong. The commit sha is pinned here.
#
# 2. The clone directory is `ultralytics-src`, NOT `ultralytics`. A directory
#    named `ultralytics` sitting next to the repo shadows the installed package
#    for any python started from that parent directory (cwd comes first on
#    sys.path, and the clone root is importable as a namespace package with no
#    __version__). Renaming it removes the failure mode entirely.
#
# --no-deps keeps pip from re-resolving torch. Ultralytics' own runtime deps are
# therefore pinned explicitly below.
